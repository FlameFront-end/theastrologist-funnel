# План стабилизации воронки

## Рабочие границы

- Всю новую реализацию создавать только в `development/frontend`.
- `work/extracted-site` не изменять: это визуальный и поведенческий эталон.
- Текущий Vercel-проект с извлечённой копией не перезаписывать до финального сравнения.
- Бэкенд не требуется. Прогресс хранить локально в браузере.
- Не переносить минифицированный JavaScript и трекеры оригинала целиком. Извлекать конкретные визуальные компоненты из отформатированного production-бандла и механически переводить их в читаемый JSX/CSS.

## Порядок работы

1. Исследовать эталон и составить карту всех экранов, ответов, переходов, промежуточных состояний и анимаций.
2. Создать здесь чистый проект React + TypeScript + Vite.
3. Организовать код по областям: `app`, `components`, `features/quiz`, `data`, `styles`.
4. Скопировать только используемые изображения и шрифты из эталона в `public`.
5. Описать шаги воронки в типизированной декларативной конфигурации.
6. Реализовать единый `QuizEngine`: ответы, переходы, возврат назад, прогресс, валидация и `localStorage`.
7. Собрать переиспользуемые шаблоны экранов вместо отдельного компонента на каждый вопрос.
8. Воспроизвести внешний вид эталона на мобильном и десктопе: размеры, шрифты, отступы, изображения, выбранные состояния и анимации.
9. Удалить аналитику и внешние запросы; отсутствующие API заменить безопасным локальным поведением.
10. Проверить основные маршруты тестами и визуально сравнить каждый экран с `work/extracted-site`.
11. Добиться чистой production-сборки без ошибок консоли и добавить README.
12. Развернуть результат отдельным preview-проектом Vercel и сравнить с текущей копией перед заменой.

## Критерии готовности

- Вся воронка проходится от начала до конца без сервера.
- После обновления страницы сохраняется текущий прогресс.
- Нет запросов к API и аналитике оригинала.
- Нет минифицированного кода оригинального приложения.
- Отличия от эталона на основных разрешениях не бросаются в глаза.
- Компоненты, данные шагов и стили можно поддерживать без разбора production-бандла.
- `npm run build` завершается успешно, а README объясняет запуск и устройство проекта.
